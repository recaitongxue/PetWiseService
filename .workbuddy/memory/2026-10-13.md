## 修 bug：trainAcc 在 mixup 下被系统性低估一半

用户贴狗模型训练日志说"太低了"（trainAcc 0.41 / valAcc 0.85）。诊断结论：**模型没问题，是指标算错了**。

- 根因 `common/train/trainer.py::train_epoch`：`correct += (outputs.argmax(1) == targets)`。mixup 分支里只替换了 `images`，`targets` 未变（仍是 A），但混合图在 lam<0.5 时以 B 为主 → 约一半样本必被判错
- 实锤：Beta(0.2,0.2) 实测 P(lam<0.5)=0.500、P(lam<0.1)=0.336（极端 U 形双峰）→ 修复前 acc ≈ 0.5×真实。用户日志 0.41×2=0.82 ≈ valAcc 0.85，吻合
- 修复：以混合权重更大的一方为准统计（`ref = targets_a if lam >= 0.5 else targets_b`；cutmix 的 lam 语义一致，因为是"保留原图的面积比"）
- 注意：**loss 一直是加权算的（训练本身健康）**，错的只是 acc 统计，不影响已训出的权重

### 读日志的几条经验（下次直接用）
- 130 类随机基线 loss = ln(130) = 4.8675；日志 e1 valLoss 4.8805 ≈ 随机 → e1 还没开始学（warmup lr 只有一半 + freeze_epochs=2 冻结骨干），正常
- lr 可反推 warmup：warm=2 时 e1 factor=0.5、e2=1.0、e3 进余弦 → 日志 1.50e-04 / 3.00e-04 / 2.99e-04 完全对上
- **trainAcc < valAcc 持续存在 ≠ 模型差**，在「强增广 + mixup + 类平衡采样」下是常态；可信指标是 valAcc（本项目 val/test 强制整图，与线上同分布）
- 狗 130 类 val top-1 0.85 / top-5 0.98 属正常偏好；top-1 与 top-5 差 13 个点说明细粒度区分不足 → 提分辨率（224→300/384）收益最大，其次换 efficientnet_v2_s / convnext_small
- e4/e5 见顶后 valLoss 回升（0.5019→0.489→0.4935）→ 已收敛，epochs 40 偏多，早停会兜住
