## 设计文档笔记持久化修复（docs/design/）

**事故**：用户昨晚在 index.html 写的改进建议全丢。原因：笔记存 localStorage，而用户是通过 present_files 的**临时静态预览服务**（`http://127.0.0.1:<随机端口>/`）打开的——该端口每次会话都变，localStorage 按 origin 隔离，今天端口已换，数据取不到。

**修复**（数据永久落盘，与端口/浏览器无关）：
- 新增 `docs/design/server.py`（Python 标准库零依赖，默认 8080）：serve index.html + flows/*.svg，`GET/POST /api/notes` 读写 `docs/design/notes.json`（POST 空值即删除该键）
- 生成器 `.workbuddy/gen_design_docs.py` 的 build_html 改为：加载时 fetch /api/notes 拉取 → 输入 debounce 400ms POST 落盘 → localStorage 仅作离线兜底；每页笔记区有「保存中…/✓ 已保存/⚠ 仅保存在本机」状态提示；保留导出 JSON 按钮
- 已验证：POST 写入 / GET 读取 / 空值删除 / 页面渲染（Edge 无头截图）全通过，notes.json 已回到 {}

**教训（重要）**：给用户的可交互 HTML 交付物，**凡需要用户输入内容的，必须服务端落盘**（本地文件或 API），不能只用 localStorage——present_files 的临时预览 origin 不稳定，用户数据会静默丢失。

**当前常驻服务**：设计文档 http://localhost:8080/（任务 FzBFyT）；移动端 dev server http://localhost:5173/（任务 kiEwzF，昨天启动的今天需确认是否还在）。
