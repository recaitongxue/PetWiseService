**行业共识（可调研方向）**：
- 宠物医疗是 AI 医疗的"先行试验田"——数据不涉及个人隐私、法规宽松、专家资源稀缺，落地比人医快。
- 胜负手从"单次诊断准确率"转向 **全生命周期档案 + 预防预警 + 生态闭环**。
- 信任是最大门槛：用户对纯 AI 信任度低，需"AI 预诊 → 真实兽医兜底"的混合模式。

## 1. 我们的竞争力定位（差异化打法）

基于现有架构（轻量可部署、可插拔知识库、规则基线兜底、开放契约），定 5 条差异化：

1. **透明溯源的 RAG**：每个结论附带引用知识片段 + 置信度 + 来源文档，而非黑盒给答案。竞品多只报"准确率 92%"不说依据——我们把"可解释"做成卖点（答辩加分）。
2. **多智能体 swarm 可扩展**：诊断 / 营养 / 行为 / 急救 各为独立专家 agent，可"毕业"新增。呼应 AgenticPet，但我们用 LangGraph 更轻、可本地跑。
3. **轻量 + 规则基线兜底**：无 LLM Key 也能跑基础分诊（已验证），答辩/离线/弱网场景友好；有 Key 再升级。
4. **开放契约优先**：OpenAPI + WebSocket frames + 预留 MCP。便于接智能硬件、宠物医院、保险机构，做"数据中枢"而非封闭 App。
5. **鼻纹身份 + 防走失比对**：竞品已验证 99.3% 可行，我们做轻量版填补国内走失寻回率<15% 的痛点。

## 3. 功能实现卡片（每个功能怎么落地）

> 每张卡：用途 → 竞争力 → 实现位置与技术 → 阶段 → 依赖 → 验收

### P0-1 拍照识别（物种 / 品种 / 皮肤病）
- **用途**：用户拍一张宠物照，识别是猫/狗及品种；拍皮肤照初筛常见病（呼应 TTcare、宠有灵犀）。
- **竞争力**：端侧 ONNX 毫秒响应，不依赖外部 API；可离线演示。
- **实现**：`services/vision` 加载 `cv/artifacts/model-<kind>-<version>.onnx`；`preprocess→engine→postprocess` 已就绪；`api` 的 `/recognitions` 调 `clients/vision.py`。需 `cv/` 训练导出 3 个权重（cat/dog/breed/skin）。
- **阶段**：P0。**依赖**：cv 权重。**验收**：单图推理 <300ms，Top-3 带置信度。

### P0-2 AI 预诊分诊（文本）
- **用途**：输入"猫吐了+精神差"，输出紧急分级 + 可能原因 + 就医建议（呼应 VetMew、汪喵灵灵）。
- **竞争力**：无 LLM 也能走规则基线（危险信号词表 + 加权评分，已验证冒烟）；有 LLM 升级为结构化报告。
- **实现**：`services/agent/app/graph/` LangGraph 编排：预处理→危险信号→检索→推理→自检→报告。`guardrails.py` 做紧急分级。
- **阶段**：P0。**依赖**：知识库。**验收**：紧急病例必带"立即就医"标记；规则基线覆盖率 ≥80% 症状。

### P0-3 知识库问答 RAG + 溯源 ★重点
- **用途**：用户问养宠知识，从权威语料检索 + 生成答案，并附引用片段。
- **竞争力**：**透明溯源**（竞品少做）——每个答案回链 `kb-*.md` 出处与段落；embedding 可插拔（本地 hash / OpenAI / 本地 bge 皆可换）；pgvector 混合检索 + rerank。
- **实现**：`services/agent/app/knowledge/` 全套已建（models/db/chunkers/loaders/vectorstore/rerank/retriever/pipeline/cli/api）。灌库：`python -m app.knowledge.cli ingest`；查询经 `retriever.hybrid_search()`。
- **阶段**：P0（已建骨架）。**依赖**：PostgreSQL + pgvector。**验收**：Top-3 召回相关片段；答案含 ≥1 处引用；切分无重复段（已修 bug，待重验）。

### P0-4 健康档案 One Pet One Profile
- **用途**：每只宠物一个档案（品种/年龄/体重/病史/过敏），贯穿所有功能（呼应 VetMew 同名理念）。
- **竞争力**：统一身份贯穿识别/问诊/提醒/保险，是生态数据底座。
- **实现**：`services/api` 新增 `app/domain/pet.py` + `repos/pets.py` + `routers/pets.py`（对应 openapi `pets` tag）；前端 `apps/mobile/src` 档案页已存在，接真实接口替换 `mock.js`。
- **阶段**：P0。**依赖**：Alembic 迁移。**验收**：档案 CRUD 通；问诊自动带入宠物上下文。

### P0-5 疫苗 / 驱虫 / 用药日历 + 提醒
- **用途**：集中管理接种、驱虫、用药计划，到期推送（呼应 PawChat、VetMew）。
- **竞争力**：与档案联动自动算下次时间；微信/站内双通道。
- **实现**：`services/api` 加 `schedules` 域 + `tasks/` 定时扫描；提醒走 `ws` 或推送。前端日程页已存在。
- **阶段**：P0。**依赖**：P0-4。**验收**：建立计划后到期触发提醒。

### P1-6 体重 / BCS 趋势与预警
- **用途**：记录体重，画图，自动算 BCS 体型分（1–9），异常波动预警（呼应 PawChat）。
- **竞争力**：趋势比单次值更有用；预警文案带"可能提示关节/代谢问题"上下文。
- **实现**：`api` 体重时序表 + 前端图表；BCS 可用 `vision` 拍照估算（预留）。
- **阶段**：P1。**依赖**：P0-4。

### P1-7 多模态排泄物 / 呕吐物识别
- **用途**：拍呕吐物/粪便/尿液，识别性状风险（呼应 VetMew 已验证场景）。
- **竞争力**：多模态是头部产品标配；与分诊联动提升准确率。
- **实现**：`vision` 新增 `kind=stool/vomit` 权重 + 后处理映射性状词典。
- **阶段**：P1。**依赖**：cv 新权重。

### P1-8 用药剂量换算 + 报告解读
- **用途**：按体重算药量；上传化验单用通俗语言解读（呼应 萌邦AI）。
- **竞争力**：降低用药风险，提升信任。
- **实现**：`agent` 加 `tools/calculator.py`(剂量公式) + `prompts/report.j2` 解读模板；知识库补充药品/指标语料。
- **阶段**：P1。**依赖**：P0-3。

### P1-9 慢病管理（糖 / 肾 / 心）
- **用途**：糖尿病/肾病/心脏病长期跟踪，定制备忘与饮食建议（呼应 PetPace、汪喵灵灵）。
- **竞争力**：从"治病"到"管病"，提高留存。
- **实现**：`agent` 加 `graph` 慢病分支 + `api` 指标时序；知识库补慢病语料。
- **阶段**：P1。**依赖**：P0-3/P0-4。

### P1-10 在线视频问诊 + 智能分诊
- **用途**：AI 预诊后一键转真实兽医视频（呼应 行业混合模式）。
- **竞争力**：解决"用户不信纯 AI"痛点；AI 先 triage 降成本。
- **实现**：`api/ws` 或 WebRTC 信令 + `agent` 预诊结果带入视频间；前端问诊页已存在。
- **阶段**：P1。**依赖**：P0-2、合规（执业兽医资质）。

### P2-11 鼻纹 / 虹膜身份（防走失）
- **用途**：拍鼻纹生成宠物"电子身份证"，走失后比对找回（呼应 宠有灵犀 99.3%）。
- **竞争力**：国内走失寻回率<15%，强痛点；可做轻量孪生网络。
- **实现**：`vision` 新模型(轻量孪生/Siamese) + 检索库；`api` 身份域。
- **阶段**：P2。**依赖**：cv 新训练。**可调研**：Siamese Network、ArcFace 宠物适配。

### P2-12 IoT 设备接入层
- **用途**：接智能项圈/猫砂盆/喂食器，数据自动入档案（呼应 PawChat、CATLINK）。
- **竞争力**：自动采集 > 手动记录，数据更准更连续。
- **实现**：`api` 加 `integrations/` 适配层(标准 JSON 入参) + 设备目录；`apps` 设备管理页。
- **阶段**：P2。**依赖**：P0-4。

### P2-13 宠物情绪 / 行为分析 Pet Translator
- **用途**：分析叫声/姿态/视频，输出情绪状态与建议（呼应 AgenticPet、Moflin）。
- **竞争力**：情感陪伴差异化；视频行为识别是前沿。
- **实现**：`agent` 加 `emotion` 专家 agent + `vision` 视频抽帧；知识库补行为语料。
- **阶段**：P2。**依赖**：P0-3。**可调研**：音频分类(喵/汪叫)、姿态估计。

### P2-14 早期疾病预测（步态 / 活动）
- **用途**：从活动/睡眠/步态微变化预警关节炎/代谢病（呼应 行业预测性分析趋势）。
- **竞争力**：从"已病"到"未病"，最高价值场景。
- **实现**：`agent` 加 `predict` 模块 + 时序异常检测；依赖 IoT/体重数据。
- **阶段**：P2。**依赖**：P2-12。

### P2-15 流浪动物 AI 识别比对
- **用途**：拍流浪动物，比对走失库/救助库（呼应 公益场景）。
- **竞争力**：公益属性提升品牌温度（呼应 汪喵灵灵公益）。
- **实现**：复用 P2-11 检索能力 + 救助库。
- **阶段**：P2。**依赖**：P2-11。

### P3-16 宠物保险一键投保 / 理赔
- **用途**：基于健康档案投保，理赔自动出材料（呼应 PawChat、Figo）。
- **竞争力**：档案即信任凭证，理赔更便捷。
- **实现**：`api` 保险域 + 接 B 端保险 API（mock 起）。
- **阶段**：P3。**依赖**：P0-4、商务。

### P3-17 社区（品种圈 / 病友圈 / 本地）
- **用途**：按品种/病种/地理位置建圈，UGC + 专家 Q&A（呼应 中研网社交趋势）。
- **竞争力**：社交留存；"病友圈"高粘性。
- **实现**：`api` 社区域(帖子/圈/评论) + `apps` 社区页(已存在)；AI 审核misinformation。
- **阶段**：P3。**依赖**：P0-4。

### P3-18 AR 训练游戏
- **用途**：手机 AR 虚拟玩具/训练，刺激宠物（呼应 Zigpoll AR 趋势）。
- **竞争力**：趣味差异化，提升日活。
- **实现**：`apps/mobile` 用设备 AR（WebAR/ARKit 封装）。
- **阶段**：P3。**依赖**：前端能力。

### P3-19 训练打卡 gamification
- **用途**：训练打卡、徽章、连胜，激励持续使用（呼应 Zigpoll）。
- **竞争力**：游戏化留存。
- **实现**：`apps` 本地 + `api` 成就域。
- **阶段**：P3。

### P3-20 开放 API / MCP 生态（B2B）
- **用途**：向医院/硬件/保险开放能力（呼应 宠有灵犀、AgenticPet MCP）。
- **竞争力**：从 App 升级为"数据中枢"，B 端变现。
- **实现**：`api` 暴露受控 OpenAPI + 预留 MCP server(`agent` 暴露工具)。
- **阶段**：P3。**依赖**：全栈稳定。

### P3-21 本地生活 / 硬件推荐
- **用途**：附近医院/宠物友好场所/用品推荐（呼应 中研网线下连接器）。
- **竞争力**：LBS + 数据驱动推荐。
- **阶段**：P3。

### P3-22 领养 / 救助
- **用途**：连接领养机构（呼应 PawChat）。
- **竞争力**：公益 + 获客。
- **实现**：`apps` 领养页 + `api` 救助域。
- **阶段**：P3。

## 4. 多智能体架构（呼应 AgenticPet 调研，我们的轻量版）

```
                 ┌─────────────┐
   用户/API ───▶ │  Orchestrator│ (LangGraph supervisor)
                 └──────┬──────┘
        ┌───────────────┼───────────────┬───────────────┐
        ▼               ▼               ▼               ▼
  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
  │诊断 Agent│   │营养 Agent│   │行为 Agent│   │急救 Agent│  ← 各持专属知识库 + 工具
  └────┬─────┘   └────┬─────┘   └────┬─────┘   └────┬─────┘
       └───────────▶ 共享 Memory + KB Retriever ◀────┘
```

- 每个 Agent = 独立提示词(`prompts/v1/*`) + 专属知识子集 + 工具集。
- "毕业"机制：新病种知识灌库后，对应 Agent 自动获得能力，无需改代码（靠 `knowledge` 子系统）。
- 当前 `services/agent` 已实现 supervisor + 诊断/急救分支骨架，营养/行为 Agent 为 P2 扩展点。

## 5. 分阶段交付路线（P0–P5）

| 阶段 | 目标 | 关键交付 | 出口标准 |
|---|---|---|---|
| **P0 核心闭环** | 端到端可用 | 铺 `api` 52 接口(优先 pets/consult/auth)、Alembic 迁移、接 PG/pgvector、cv 导出首批权重、agent 接真实 LLM Key、知识库切分重验 + 灌库 | 拍照识别 + 文本分诊 + 知识库问答 三件套在演示环境跑通 |
| **P1 健康纵深** | 从工具到管家 | 体重/BCS、用药换算、报告解读、慢病、视频问诊 | 单宠健康档案贯通 ≥5 个功能 |
| **P2 身份/硬件** | 多模态与物联 | 鼻纹身份、IoT 接入、宠物翻译、早期预测、流浪比对 | 防走失 + 硬件数据入档 demo |
| **P3 生态** | 社交与商业 | 社区、保险、AR、gamification、开放 API/MCP | 形成可演示的生态闭环 |
| **P4 基建** | 工程化 | `infra` 补 vision/agent Dockerfile、CI、监控、契约 codegen 流水线 | 一键 `compose up` 全栈 |
| **P5 打磨** | 答辩/上线 | 压测、安全审计、文档、演示脚本 | 答辩就绪 |

**建议顺序理由**：先把 P0 三件套打通（一条读/一条写/一条流式），比一次性铺开稳；知识库是放大器，越早灌真实语料越好。

## 7. 风险与建议

1. **信任门槛**：纯 AI 诊断用户不买账——坚持"AI 预诊 + 真实兽医兜底"混合模式，并在 UI 显式免责声明（合规必需）。
2. **数据合规**：健康数据涉及隐私，PG 加密 + 访问审计；对外 API 走 token；未来出海需 GDPR/CCPA。
3. **权重质量**：cv 训练数据决定识别上限，优先保证 cat/dog/breed/skin 四类标注质量；无 GPU 时先用公开预训练权重微调。
4. **LLM 成本**：默认规则基线兜底，真实 LLM 走可配置 provider；知识库溯源降低幻觉。
5. **毕设取舍**：P0 三件套 + 知识库溯源 + 鼻纹演示，足以体现"技术深度 + 产品完整度"；P1–P3 作为"未来工作"章节展示格局。
